# WHU-MARS / UAD 核心复现：A800 单卡启动手册

## 1. 本轮复现边界

本轮只复现 WHU-MARS-1000 上论文 Table 8 的四组 AS-ReID 实验：

| 实验 | `SOLVER.LOSS_TYPE` | 训练目标 | 论文参考结果（mAP / R-1 / R-5 / R-10） |
|---|---|---|---|
| Baseline | `base` | `L_ce + L_WRT` | 8.9 / 23.9 / 41.4 / 50.5 |
| ProCA only | `base+pca` | `L_base + 0.01 L_ProCA` | 9.3 / 24.5 / 42.0 / 50.7 |
| GPD only | `base+gpd` | `L_base + 1.0 L_GPD` | 10.9 / 28.7 / 45.9 / 54.2 |
| Full UAD | `base+pca+gpd` | `L_base + 0.01 L_ProCA + 1.0 L_GPD` | 11.0 / 29.5 / 46.3 / 54.8 |

不在本轮范围：WHU-MARS-2337、AG-ReID、VI-ReID、MM-ReID、3×3 模态矩阵、Figure 4 可视化以及其他 SOTA。

## 2. 论文与代码对应关系

论文第 4.2 节（第 5 页）定义共享 ViT、BNNeck、CE、WRT 和 `P×M×K` sampler；第 4.3 节（第 6 页）定义 ProCA；第 4.4 节（第 6 页）定义 GPD；第 5.1 节（第 6–7 页）给出训练配置；Table 8（第 8 页）给出四组目标结果。

当前代码与官方仓库 `msm8976/WHU-MARS` 的 `main` 提交 `3e2a07314119402586c76096e87d40420894ad30` 逐文件一致。核心入口如下：

| 部分 | 文件 | 功能 |
|---|---|---|
| 数据解析 | `datasets/whu_mars.py` | 读取 `train/query/test` 下的 RGB、IR、Thermal 图像并解析 PID、camera ID |
| P×M×K 采样 | `datasets/sampler.py` | 每批选择 16 个身份，每个身份每模态 4 张图像 |

## 3. 必须明确的官方实现口径

1. `SOLVER.IMS_PER_BATCH=64` 是 sampler 输出的逻辑样本数。每个逻辑样本包含 RGB、IR、Thermal 三张图，因此模型实际前向图像数为 `64×3=192`，对应论文的单 GPU batch size 192。单卡运行不能把该值改成 192，否则实际会前向 576 张图。
2. 论文写 EMA 旧原型系数 `α=0.8`。代码配置 `MODEL.GPD_MOMENTUM=0.2` 表示新中心系数，更新式是 `0.8×old + 0.2×new`，二者等价。
3. 论文第 6 页描述包含 random resized cropping；官方公开代码实际执行 `Resize → RandomHorizontalFlip → Pad → RandomCrop → RandomErasing`。本轮以官方代码为复现基准，不自行替换增强。
4. 论文 Table 2 将 WHU-MARS-1000 train 写为 92,313 张、总计 185,922 张；实际已授权数据和官方仓库修正后的统计是 train 92,133 张、gallery 93,609 张、总计 185,742 张。预检以实际官方数据为准。
5. `DATASETS.ROOT_DIR` 必须传数据集父目录 `/mnt/cache/wanghanzhi/Datasets`；loader 会自行追加 `WHU-MARS`。不要传 `/mnt/cache/wanghanzhi/Datasets/WHU-MARS`，否则路径会重复。
6. 训练过程每 10 epoch 在 query/test split 上评测，但正式结果固定报告 epoch 120，不按 test 指标挑选 epoch。若查看中间最优值，只能标记为 `test-selected exploratory screening`。

### 5.1 首次启动失败说明

首次 Baseline/UAD 命令没有进入训练。异常参数尾部为：

```text
'OUTPUT_DIR', 'cd', '/mnt/cache/wanghanzhi/XK/CVPR26_UAD/outputs/...'
```

这表示 shell 将 `cd` 错误地放进了 `train.py` 的命令行，令 `OUTPUT_DIR` 后出现两个值，YACS 因覆盖参数为奇数而终止。该失败未加载数据、未构建模型、未写入 checkpoint，不属于训练数值失败。所谓 UAD 失败日志仍显示 `SOLVER.LOSS_TYPE base` 和 Baseline 输出目录，说明实际重复执行的是 Baseline 命令，而不是 `configs/UAD.yml`。

修正后的脚本会先打印 `RUN=... CONFIG=... LOSS_TYPE=...`。请直接运行脚本，不要把 `cd` 拼接到 `OUTPUT_DIR` 行，也不要手工复用 Baseline 命令启动 UAD。

## 9. 验收与异常停止条件

每组至少确认：

1. 日志出现 `Epoch[1]`，证明不是只有调度或 shell 启动成功；
2. 训练完成 `Epoch 120`，生成 `transformer_120.pth`；
3. epoch 120 自动评测和独立复评的 mAP、Rank-1、Rank-5、Rank-10 一致到合理浮点误差；
4. 四组只改变目标损失，数据、seed、backbone、预训练权重、采样、优化器和评测协议保持相同；
5. Baseline 若与论文相差超过约 1.0 个 mAP 百分点或 2.0 个 Rank-1 百分点，先停在 Baseline 排查，不继续把偏差传播到后三组；
6. 重点比较 matched deltas：ProCA 对 Baseline、GPD 对 Baseline、Full UAD 对 Baseline。单次复现不应直接宣称统计显著性或方法优越性。

常见优先检查项：数据目录是否重复追加 `WHU-MARS`、逻辑 batch 是否误设为 192、是否使用 `TEST.NECK_FEAT=before`、同相机过滤是否被改动、三模态顺序是否保持 RGB/IR/Thermal、GPD 的 `0.2` 是否被误改成 `0.8`。

## 1. 实验目的

本轮建立新的 `fair_baseline_v2`，统一修正以下三项实验口径：

1. CLIP ViT-B/16 实际启用与 ImageNet ViT 相同的 stochastic depth；
2. 所有 optimizer 参数组按照各自初始 LR 等比例执行 warm-up 和 cosine decay；
3. backbone 构造、公共 head、PKM sampler 和 DataLoader worker 使用相互隔离的随机流。

此前完成的 ViT 与 CLIP 结果保留为历史结果，不与本轮结果混合作严格 matched comparison。

旧 launcher 若在当前代码上重新执行，也会继承新的 scheduler、RNG 和 CLIP DropPath 行为，因此不能再生成旧口径结果。需要复现历史口径时应使用旧源码提交 `93d3587`；当前代码只用于 `fair_baseline_v2`。

## 2. 统一公平性契约

### 2.1 DropPath

ViT 与 CLIP 均使用：

```text
MODEL.DROP_PATH=0.1
```

12 个 Transformer block 的 drop-path rate 线性变化：

$$
d_l=0.1\frac{l}{11},\qquad l=0,\ldots,11
$$

attention 和 MLP 两条残差分支均应用 DropPath。CLIP 内部为 sequence-first 张量，实现中先转换为 batch-first，保证 mask 按图像样本生成，而不是按 token 生成。

### 2.2 逐参数组 scheduler

每个参数组以其自身初始学习率 $LR_g^{init}$ 计算：

$$
LR_g^{warmup}=0.01LR_g^{init}
$$

$$
LR_g^{min}=0.002LR_g^{init}
$$

因此 backbone non-bias、backbone bias 和新层之间的倍率在整个训练周期保持不变，不再根据 `BACKBONE_LR` 是否为正数切换 scheduler 语义。

### 2.3 随机流隔离

统一使用：

```text
SOLVER.SEED=1234
```

派生随机流：

| 随机对象 | seed |
|---|---:|
| backbone 临时初始化 | 1235 |
| 公共 classifier / BNNeck | 1236 |
| PKM sampler | 1334 |
| train DataLoader workers | 1434 |

backbone 构造与公共 head 初始化均使用 `torch.random.fork_rng`，不会改变外部全局 RNG。PKM sampler 使用自己的 Python/NumPy RNG；DataLoader 使用独立 `torch.Generator` 和 worker seed。ViT 与 CLIP 因而具有相同的公共 head 初始化、采样顺序和数据增强随机流。

该随机性契约按本项目正式实验边界实现于 `MODEL.DIST_TRAIN=False`、`WORLD_SIZE=1`。DDP sampler 不属于本轮验收范围。

同时固定：

```text
torch.backends.cudnn.deterministic=True
torch.backends.cudnn.benchmark=False
```

## 4. ViT 四组 UAD 消融

四组均使用 ImageNet ViT-B/16、0.5 normalization、backbone LR 0.008。

| 编号 | 配置 | 损失 | 目的 |
|---|---|---|---|
| V1 | `configs/fair_vit_baseline.yml` | `L_base` | 新统一 ViT Baseline |
| V2 | `configs/fair_vit_proca.yml` | `L_base + 0.01 L_ProCA` | ProCA 独立贡献 |
| V3 | `configs/fair_vit_gpd.yml` | `L_base + L_GPD` | GPD 独立贡献 |
| V4 | `configs/fair_vit_uad.yml` | `L_base + 0.01 L_ProCA + L_GPD` | Full UAD |

核心差分：

```text
V2 - V1：ProCA
V3 - V1：GPD
V4 - V1：Full UAD
V4 - V2：在 ProCA 上加入 GPD
V4 - V3：在 GPD 上加入 ProCA
```

## 5. CLIP 五组迁移实验

所有 CLIP 组使用 768D pre-projection CLS feature，并实际启用 DropPath 0.1。

| 编号 | 配置 | 损失 | Norm | Backbone LR |
|---|---|---|---|---:|
| C1 | `configs/fair_clip_baseline_lr008.yml` | `L_base` | 0.5 | 0.008 |
| C2 | `configs/fair_clip_baseline_lr0008.yml` | `L_base` | 0.5 | 0.0008 |
| C3 | `configs/fair_clip_uad_lr008.yml` | Full UAD | 0.5 | 0.008 |
| C4 | `configs/fair_clip_uad_lr0008.yml` | Full UAD | 0.5 | 0.0008 |
| C5 | `configs/fair_clip_uad_imagenet_norm_lr008.yml` | Full UAD | ImageNet | 0.008 |

核心 matched comparisons：

```text
C1 ↔ C2：CLIP Baseline backbone LR
C3 ↔ C4：CLIP + UAD backbone LR
C1 ↔ C3：LR 0.008 下 UAD 增益
C2 ↔ C4：LR 0.0008 下 UAD 增益
C3 ↔ C5：LR 0.008 下 normalization
V1 ↔ C1：相同 loss/norm/LR 下替换 backbone
V4 ↔ C3：相同 UAD/norm/LR 下替换 backbone
```

## 6. 结果解释边界

1. V1–V4 可以作为严格的四组 UAD 消融。
2. C1–C5 可以回答 CLIP 上 UAD、backbone LR 和 normalization 的影响。
3. V1↔C1、V4↔C3 除 backbone 及其预训练来源外，其余训练口径保持一致。
4. 单 seed 结果用于确定性第一轮筛选，不宣称统计显著性。
5. epoch 10–110 的 test split 指标仅用于健康检查；若观察中间最优结果，必须标记为 `test-selected exploratory screening`。
6. 旧版 CLIP 无 DropPath 结果和旧版 ViT legacy scheduler 结果只作为历史参考。

后续加入新模块时，新模块若需要独立 LR，应建立明确的 optimizer 参数组；其初始化应使用独立的 `fork_rng` 派生 seed。关闭该模块时不得实例化模块或消耗其初始化随机数。
